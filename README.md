# 增量构建裁决台

面向大型单仓库的增量构建裁决服务：导入任务图后，按"定义 / 源文件 / 所读上游产物摘要"
三重匹配裁决每个任务是**可复用**、**待上游**还是**可执行**；执行结果经输入指纹核对后
原子更新依赖关系与计划，浏览器页面以原生 JavaScript 实时查看计划与最短失效原因链。

- 后端：Python + FastAPI，状态存 SQLite（WAL）
- 前端：单页原生 JavaScript，轮询增量计划（仅返回变动项）
- 性能：10 万任务 / 20 万依赖下，1000 次上报 + 增量计划查询总计 < 10 秒
- 重启后从 SQLite 完整恢复，裁决一致

## 快速开始（Docker Compose）

```bash
docker compose up --build
```

然后访问构建裁决页面：<http://localhost:8000>

页面上可以：

1. 点击 **导入演示图** 生成一个 200 任务的示例依赖图；
2. 查看各状态任务列表（可执行 / 待上游 / 可复用 / 已完成）与右侧**变更流**；
3. 点击任意任务查看摘要对比、依赖关系与**最短失效原因链**；
4. 点击 **执行一步**（或打开 **自动执行**）模拟领取与上报，观察计划实时演变——
   上游产物摘要不变时下游直接复用，变化时下游按拓扑序转为可执行。

## 裁决语义

每个任务在导入时携带：本轮与上次执行的**定义摘要**与**源文件摘要**、静态前置任务、
上次发现的**动态前置任务**、上次执行读到的**上游产物摘要**以及自身上次产物摘要。

| 状态 | 含义 |
| --- | --- |
| `reusable` 可复用 | 定义、源文件、所读上游产物摘要全部与上次执行一致 |
| `waiting` 待上游 | 存在未落定（非可复用/已完成）的上游，须先等待 |
| `executable` 可执行 | 上游全部落定，但自身输入与上次执行不一致 |
| `done` 已完成 | 本轮结果被接受（终态） |

- **最短失效原因链**：失效任务携带从根因到自身的最短链路（自身原因为 1 跳，
  否则取原因链最短的上游 + 1 跳），在页面任务详情中展示。
- **输入指纹**：领取任务时返回 `fingerprint = H(定义, 源文件, 各依赖当前产物摘要)`；
  上报时服务端重新核对，指纹不符或读取摘要与当前不一致即视为**过期结果**，
  拒绝且不改任何状态。
- **原子更新**：被接受的结果在同一事务内更新"上次执行记录"、动态依赖、产物摘要，
  并沿反向边增量重算受影响的下游；动态依赖 = 实际读取 − 静态依赖。
- **整次上报回滚**：新依赖引用不存在的任务或形成环路时，整批结果回滚（HTTP 409），
  计划与依赖关系保持不变。
- **产物不变则复用**：上游重跑但产物摘要与上次一致时，下游读取记录仍然匹配，
  维持可复用，不重跑。
- **重启一致**：所有状态存于 SQLite，重启后完整恢复，裁决结果不变。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/graph/import` | 导入任务图（整图替换 + 全量裁决，单事务） |
| `GET` | `/api/plan?since=N` | 增量计划：仅返回版本 N 之后变化的任务 |
| `GET` | `/api/summary` | 各状态计数与当前计划版本 |
| `GET` | `/api/tasks?state=…` | 按状态分页列出任务 |
| `GET` | `/api/tasks/{id}` | 任务详情（摘要、依赖、历史读取、原因链、指纹） |
| `POST` | `/api/claim` | 领取可执行任务，返回输入指纹与各依赖当前产物摘要 |
| `POST` | `/api/results` | 上报执行结果（可批量）；过期结果拒绝，成环/引用缺失整批回滚 |
| `POST` | `/api/demo/seed`、`/api/demo/step` | 演示辅助：生成示例图 / 模拟执行一步 |

### 导入项示例

```json
{
  "tasks": [{
    "id": "//app:foo",
    "def_digest": "d1", "src_digest": "s1",
    "prev_def_digest": "d0", "prev_src_digest": "s0",
    "prev_artifact_digest": "a0",
    "static_deps": ["//lib:a"],
    "dyn_deps": ["//lib:b"],
    "prev_reads": {"//lib:a": "ra", "//lib:b": "rb"}
  }]
}
```

### 上报示例

```json
{
  "results": [{
    "task_id": "//app:foo",
    "fingerprint": "<领取时返回的指纹>",
    "reads": {"//lib:a": "ra", "//lib:b": "rb2"},
    "artifact_digest": "a1"
  }]
}
```
